## 1. 八项需求落地

1. 保存和复用：新增题目中心，独立创建或从问卷保存。不同问卷可使用同一正式版本，局部 `qid` 不必相同。
2. 分享题目：按用户名授权指定版本或全部现有及未来版本；可控制是否允许派生。共享用户不能覆盖原作者版本。
3. 发布后保护：`ever_published` 永久标记与服务端结构比较共同保护题目、选项、约束、顺序、必填及跳转规则；关闭不解锁。复制为新草稿后再修改。
4. 历史与恢复：版本内容只新增、不覆盖；保存父版本、作者、说明及恢复来源。恢复旧内容创建新版本，不移动或删除旧版本。
5. 多版本并存：支持从任意同系列父版本分支；问卷固定引用版本，推荐版本变化不影响旧问卷。
6. 使用情况：题目详情列出当前用户有权查看的引用问卷及实例版本，不泄露其他用户的私有问卷标题。
7. 题库：私人题库支持创建、修改、归档、加入、移除及固定版本切换。移出或升级条目不删除题目、不影响已有问卷。
8. 跨问卷统计：按版本汇总实际答案，支持日期范围、作答次数、去重答卷数、覆盖问卷数、选项分布、数字均值及区间分布；版本之间分别计算。

## 2. 身份与数据结构

保留第一阶段的 `users / surveys / responses / stats`，新增以下五个集合。

- `question_series`：所有者、名称、标签、推荐版本、CAS 修订号、共享授权、工作草稿、归档时间与可选迁移来源键。
- `question_versions`：系列、版本号、父版本、恢复/派生来源、创建者、修改说明、完整性标记、不可变题目内容。
- `question_banks`：所有者、名称、说明、归档状态与修订号。
- `question_bank_items`：题库、系列、固定版本、条目修订号。同一题库不能重复收录同一系列。
- `legacy_question_bindings`：旧问卷 ID、旧问卷修订号、局部 qid、快照指纹到系列及版本的外置关联；保留依据和可信等级。

局部 `qid` 只用于当前问卷中的答案和跳转；`question_series_id` 标识题目家族；`question_version_id` 标识不可变内容；问卷 `version` 与系列 `revision` 是并发控制号，不是题目版本号。

问卷实例保存全局引用、物化内容和本卷的必填、顺序、跳转配置；答卷保留完整提交快照、访问路径及实际到达题目的答案。不能用题干、选项或 SHA 摘要替代全局身份。同标题的不同题目不会被自动合并。

全部新增集合配置 MongoDB JSON Schema 与必要索引。关键唯一索引包括 `(series_id, version_no)`、`(bank_id, series_id)`、旧快照复合身份及迁移来源键。已有去重索引保留。

## 3. 草稿、并发与一致性

临时题目在问卷草稿中直接编辑，显式保存到题目中心或发布时才创建正式版本；发布自动封存采用确定性来源键，重试不重复创建。正式题目也可单独保留工作草稿，不污染正式版本历史。

所有修改系列、共享、题库和条目操作使用修订号做 CAS。问卷保存、发布、关闭同时检查旧修订号与状态，防止“保存草稿”覆盖并发发布。前端遇到 409 保留本地编辑，不自动用服务器数据覆盖输入；用户可明确刷新。

提交前读取统计缓存修订号，答卷插入后仅在修订号仍匹配时增量更新。如果并发提交或重建已推进修订号，则改为从答卷快照重建，避免“已被重建包含的答卷又执行一次 $inc”。重建自身也使用 CAS，冲突有限重试。

答卷已经持久化而统计缓存更新失败时，返回提交成功及 `stats_pending=true`，不诱导用户重复提交。读取统计时比较答卷数和缓存总数并修复。缓存是派生数据，不是答卷来源；这提供可恢复的最终一致性，不宣称跨集合事务或强一致快照。该校验增加一次索引计数查询，不能再将完整统计接口复杂度严格称为 O(1)。

版本序号预留、插入版本、更新推荐指针是多个单文档操作，而非事务；异常时可能出现序号空洞或推荐指针未推进，但既有不可变版本和问卷不会被覆盖。后续大规模部署可采用副本集事务进一步收紧提交边界。

## 4. 权限与统计口径

- 题目共享只授予内容查看/使用权；统计授权由问卷所有者在编辑器的“单题统计授权”中单独指定。
- 统计先筛选当前用户自己的问卷与明确授予该版本聚合权限的问卷，再展开快照、对齐局部答案并聚合。显式指定无权问卷返回 403。
- 撤销共享后已有问卷继续保存并使用其冻结副本；不能新增引用、复制为新引用或派生。归档同样不破坏历史答卷。
- 跨用户文本只显示聚合数量；原始文本分页仅来自自己问卷，不返回其他用户的填写者身份。
- 共享列表搜索仅匹配接收者能看见的版本标题，不能通过搜索命中未共享版本的新标题。
- 同版本在同份答卷出现两次时，`answer_count` 计两次，而 `response_count` 计一份答卷；不声称是去重人数。
- 多选比例分母为有效作答次数，比例和可能超过 100%。数字均值为全部有效答案的总和除以数量，绝非“各问卷均值的平均”。
- 跨版本默认不合并；缺失、空答、非有限或非法数值不计入有效数字样本。历史快照原本没有的约束不会被猜测补写。

跨问卷查询由 MongoDB 聚合管道完成，使用 `$unwind / $filter / $facet / $group / $bucketAuto`，没有使用按用户不分权限的公共缓存。

## 6. 安全迁移与回滚

迁移前停止应用写入，仅保留 MongoDB；`--apply` 会先生成独立 BSON ZIP 备份。默认预演不初始化集合、不回填数据。

在 `backend` 目录执行：

```powershell
.venv\Scripts\python.exe scripts/migrate_stage2.py --database survey_db --uri mongodb://127.0.0.1:27017
.venv\Scripts\python.exe scripts/migrate_stage2.py --database survey_db --uri mongodb://127.0.0.1:27017 --apply
```

当前问卷缺失身份时创建题目版本并附加引用，但不增加原问卷业务修订号。只有问卷修订号、qid 及快照可见内容一致时，旧答卷才关联当前版本；否则建立独立的 `snapshot_only` 历史版本，明确约束未知，不允许直接用于新问卷或无条件恢复。

所有旧答卷保持原样，迁移通过外置关联参与统计。迁移前后对按 `_id` 排序的原始 BSON 流做 SHA-256 校验；重复执行不会重复建版本或关联。迁移遇到并发修改/孤儿答卷会记录冲突并返回非零退出码，不静默猜测。


## 8. 人工演示顺序

1. 创建一题，保存 v1；分别放入两份问卷，确认局部 qid 不同也能统一统计。
2. 发布并填写样本；回到编辑器确认题目只读，关闭后仍只读。
3. 在题目详情从 v1 新建 v2，再从 v1 分支；检查原发布问卷仍绑定 v1。恢复 v1 生成下一版本。
4. 创建题库、收录 v1、手动升级条目；确认旧问卷没有变化。
5. 使用第二账号验证指定版本共享、禁止派生和撤销；不能查看其他用户原始答卷。
6. 由问卷所有者单独开放该题版本的聚合授权；确认跨问卷数量增加，跨用户文本明细仍不可见，撤销授权后立即移除该范围。
7. 查看日期过滤及多版本概览，确认不混算不同版本；运行一键回归作为可重复验收证据。

## 9. 已知边界

这是课程规模实现，不宣称公网生产就绪。部署前必须替换开发 JWT 密钥、配置数据库认证、HTTPS 与反向代理，并进一步加入限流、审计、持久任务及容量测试。共享列表为保证授权后的搜索语义，会遍历候选共享题目，海量数据时应改为按授权版本建立可检索投影。题库选择下拉目前最多加载 100 个题库，超大规模可继续补充服务端搜索。

Starlette 测试客户端有一条关于 httpx 的弃用提示；当前测试通过，不在本次需求中无关升级依赖。前端大块依赖仍可能触发 Vite 体积警告，不影响构建成功；此处不将警告伪报为已消除。
