# 项目完成报告（第一阶段）

## 1. 项目目标

开发一个简化版在线问卷系统（类似问卷星 / Google Forms）：
注册用户创建问卷 → 通过 URL 分发 → 其他用户填写 → 系统自动统计。
重点考察 MongoDB 数据库设计、后端逻辑、数据结构与业务逻辑建模、
条件逻辑与跳转逻辑的实现，以及 AI 编程工具的使用规范。

## 2. 系统设计

技术选型：**FastAPI（Python）+ MongoDB + Vue 3 + Element Plus + ECharts**。

- 后端"引擎与接口分离"：跳转引擎、校验引擎、统计引擎为独立纯函数模块，
  可单独单元测试；接口层只做鉴权与参数解析。
- 前端五页面：登录注册、问卷工作台、编辑器（三栏 + 拖拽 + 实时预览）、
  填写端（单题一屏 + 进度条）、统计面板（ECharts）。
- 详见 `docs/系统说明.md`。

## 3. MongoDB 设计

四个集合：`users` / `surveys`（题目与跳转规则内嵌）/
`responses`（含**问卷快照**）/ `stats`（`$inc` 预聚合）。

核心论证（为什么用 MongoDB）：问卷"整体读写 + 答卷需固化问卷结构"的特征
恰是文档模型主场 —— 内嵌替代 join、快照替代历史表。
详见 `docs/数据库设计.md`。

## 4. 跳转设计

问卷建模为**有向图**：节点 = 题目，边 = 跳转规则 + 顺序边。
规则声明式存储（数据驱动，不硬编码）；执行引擎模拟整卷流程得到 visited 集合；
保存时做 **DFS 三色环检测**（拒绝循环）与**可达性死题检测**（警告不可达题目）。
支持单选 eq、多选 contains/count_gt/count_eq、数字 gt/lt/eq/range 六种算子。

## 5. 校验设计

声明式校验引擎：约束全部来自题目文档字段，校验器按题型映射规则解释函数，
新增题型只加规则不改代码。**只校验实际到达的题目**（跳过跳转绕开的必答题），
错误统一 `{question_id, message}` 格式供前端定位。

## 6. AI 使用过程

见 `docs/AI使用日志.md`。总结：

- **AI 帮了什么**：项目脚手架、Vue 页面样板、ECharts 图表配置、文档初稿
- **AI 做错了什么**：
  - 生成的统计读取把 MongoDB `$inc` 的字符串键对象当数组下标访问（KeyError），
    需改为字符串键字典存储并兼容读取；
  - 忘记填写端接口要下发跳转规则（否则前端无法镜像跳转）；
  - 生成的乐观锁示例没有处理"自动保存连续触发"导致的版本快速递增。
- **自己设计/修正了什么**（核心设计均为自己设计）：
  响应快照机制、跳转图模型与两个图算法、双通道统计、稳定摘要键计数、
  respondent_key 原子去重、visited 过滤答案、"必然命中"判定顺序边失效。

## 8. 遇到的问题与解决

| 问题 | 原因 | 解决 |
|------|------|------|
| 统计计数 KeyError | MongoDB `$inc` 把数字下标存成字符串键对象 | 统一按字符串键存储/读取（`_read_counts`） |
| 统计接口 500（ObjectId 不可序列化） | 响应里直接返回了 ObjectId | 接口层统一转 str |
| 截止时间比较 TypeError | MongoDB 读回的 datetime 无时区 | `_as_utc` 统一转 UTC 感知时间 |
| 填写端不跳转 | 填写接口未下发 jump_rules | 补上下发，前端镜像跳转，服务端仍权威执行 |
| 未登录访客能看到非匿名问卷题目 | 登录校验只放在提交接口 | 获取问卷接口同样强制登录（401） |
| 保存冲突 409 频发 | 自动保存与手动保存并发 | 版本号由后端管理，前端保存后立即同步新版本 |
| 登录后无法回到原问卷 | after_login 存的 hash 串被路由误解析 | 去掉 `#` 前缀再 push |
| 合法单选跳转规则被拒绝 | 字符串 `eq` 规则误进入数字阈值校验 | 按题型区分选项校验与数值校验，并增加回归测试 |
